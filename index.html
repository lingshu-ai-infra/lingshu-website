LingShu AI Infra

灵枢 AI Infra
Pool Engine for GPU Workloads

Open-source distributed GPU resource pool scheduling service. Built on SpringBoot + Netty + Protobuf. Replaces K8s static GPU binding with shared, dynamic, multi-tenant GPU pools — zero GPU dependency in business pods.

Why LingShu AI Infra

Not another K8s Operator — GPUs treated as a pool

①

Pool, not static binding

Business pods no longer monopolize a GPU. All GPUs flow into a unified scheduler pool with dynamic placement based on real-time memory, util, and queue depth. Target utilization ≥ 70%.

②

Multi-dim load balancing

Composite score mem×0.5 + util×0.3 + queue×0.2; same-node affinity preferred, automatic queueing when saturated.

③

Three-tier GPU isolation

MIG (hardware partition) · MPS (process group) · Soft (single CUDA context). Auto-selected by business grade. No cross-tenant memory leaks.

④

Four-tier out-of-band

Same-node SHM → cross-node RDMA → NAS (CephFS/JuiceFS/Lustre) → cross-AZ object storage. Metadata goes via RPC; payload goes direct.

⑤

Self-built leader election

Multi-round voting + force ballots + RESET_CONTROLLER against split-brain. No Etcd needed — built atop our existing SpringBoot stack.

⑥

State machine + idempotent assignment

PENDING → QUEUED → ASSIGNED → RUNNING → SUCCESS/FAILED/TIMEOUT/ORPHAN. Idempotency-Key prevents double-dispatch.

⑦

Lightweight business pods

No CUDA, no PyTorch, no TensorRT, no GPU device mounts. Image drops from 8 GB+ to under 200 MB. Cold start in seconds.

Architecture

Four decoupled layers: Business → Gateway → Scheduler → Worker

┌─────────────────────────────────────────────────────────────┐ │ Layer 1 — Business Pods (Client) │ │ No GPU / No CUDA / Image < 200MB │ └──────────────────────────────┬──────────────────────────────┘ │ Netty-RPC over TCP │ (reuse cloud-basic Protobuf) ▼ ┌─────────────────────────────────────────────────────────────┐ │ Layer 2 — Gateway (Java + cloud-basic) │ │ Long connection pool · Rate limit · Quota · Routing │ └──────────────────────────────┬──────────────────────────────┘ │ SubmitTask / QueryTask ▼ ┌─────────────────────────────────────────────────────────────┐ │ Layer 3 — Scheduler (Cluster, Leader-elected) │ │ ControllerManager election · Resource view · Load balancer │ │ State machine · Idempotency key · Heartbeat reconciliation │ │ MySQL persistence │ └──────────────────────────────┬──────────────────────────────┘ │ WorkerHeartbeat / Dispatch ▼ ┌─────────────────────────────────────────────────────────────┐ │ Layer 4 — Worker Pool (Java → Rust evolution) │ │ MIG/MPS/Soft 3-tier isolation · PyO3 / Sidecar Python Op │ │ SHM/RDMA/NAS/Object 4-tier large-tensor transport │ └─────────────────────────────────────────────────────────────┘

MIG (hardware partition) / MPS (process group) / Soft (single CUDA context); out-of-band transport keeps metadata on RPC and payload direct.

Quick Start

Drop the Client SDK into your business pod; submit tasks to the pool in one line.

<!-- pom.xml -->
<dependency>
  <groupId>ai.lingshu.infra</groupId>
  <artifactId>lingshu-gpu-client</artifactId>
  <version>0.1.0-alpha</version>
</dependency>
// build.gradle
dependencies {
    implementation 'ai.lingshu.infra:lingshu-gpu-client:0.1.0-alpha'
}
// SubmitAndQueryDemo.java
public class SubmitAndQueryDemo {
    public static void main(String[] args) throws Exception {
        try (GpuClient client = new GpuClient("gateway.lingshu-infra:2381")) {
            String taskId = client.submit(SubmitTaskRequest.newBuilder()
                .setOpId("text_classification")
                .setInput("Pool scheduling really works")
                .setPriority("high")
                .setTimeoutMs(200)
                .build());

            QueryTaskResponse result = client.query(taskId);
            System.out.println("status=" + result.getStatus()
                + " output=" + result.getOutput());
        }
    }
}
# application.yml — business pod config
lingshu:
  gpu:
    client:
      gateway: gateway.lingshu-infra:2381
      connect-timeout-ms: 3000
      retry: 3
    submit:
      default-op: text_classification
      default-priority: normal
      default-timeout-ms: 200
