LingShu AI Infra

灵枢 AI Infra
Pool Engine for GPU Workloads

Open-source distributed GPU resource pool scheduling service. Built on SpringBoot + Netty + Protobuf. Replaces K8s static GPU binding with shared, dynamic, multi-tenant GPU pools — zero GPU dependency in business pods.

Quick Start → Star on GitHub

$gpush submit \
--op text_classification \
--input "灵枢调度真的很强" \
--priority high --timeout-ms 200

Why LingShu AI Infra

不是又一个 K8s Operator,是把 GPU 当池子用

①

资源池化,不是静态绑定

业务 Pod 不再独占 GPU 卡。所有 GPU 资源进入统一调度池,基于实时显存/算力/队列做动态分配,目标整体利用率 ≥ 70%。

②

多维度负载均衡

综合评分 score = mem×0.5 + util×0.3 + queue×0.2,同节点亲和优先,无可用节点自动排队。

③

三档 GPU 隔离

MIG 硬件切分(强)· MPS 进程组切分(中)· 单进程 CUDA context(软)。按业务等级自动选档,显存硬隔离不串扰。

④

四档 Out-of-band 传输

同节点共享内存 → 跨节点 RDMA → NAS(CephFS/JuiceFS/Lustre)→ 跨可用区对象存储。metadata 走 RPC,payload 直传。

⑤

ControllerManager 自研选主

多轮投票 + force 票 + RESET_CONTROLLER 反脑裂。无需 Etcd/Consul,基于现有 SpringBoot 自研组件即可。

⑥

任务状态机 + 幂等分配

PENDING → QUEUED → ASSIGNED → RUNNING → SUCCESS/FAILED/TIMEOUT/ORPHAN 全生命周期,Idempotency-Key 防双发。

⑦

业务轻量化

Pod 镜像无需 CUDA/Torch/TensorRT,无需挂载 GPU 设备。瘦身后的业务镜像从 8GB+ 降到 < 200MB,冷启动秒级。

Architecture

四层解耦:业务 → 网关 → 调度 → Worker

┌─────────────────────────────────────────────────────────────┐ │ Layer 1 — Business Pods (Client) │ │ 无 GPU / 无 CUDA / 镜像 < 200MB │ └──────────────────────────────┬──────────────────────────────┘ │ Netty-RPC over TCP │ (复用 cloud-basic Protobuf) ▼ ┌─────────────────────────────────────────────────────────────┐ │ Layer 2 — Gateway (Java + cloud-basic) │ │ 长连接池 · 限流配额 · 协议解析 · 路由转发 │ └──────────────────────────────┬──────────────────────────────┘ │ SubmitTask / QueryTask ▼ ┌─────────────────────────────────────────────────────────────┐ │ Layer 3 — Scheduler (Cluster, Leader-elected) │ │ ControllerManager 选主 · 资源视图 · 负载均衡 · 任务队列 │ │ 状态机 · 幂等键 · 心跳对账 · MySQL 持久化 │ └──────────────────────────────┬──────────────────────────────┘ │ WorkerHeartbeat / Dispatch ▼ ┌─────────────────────────────────────────────────────────────┐ │ Layer 4 — Worker Pool (Java → Rust 演进) │ │ MIG/MPS/Soft 三档隔离 · PyO3 / Sidecar Python Op 集成 │ │ SHM/RDMA/NAS/Object 四档大张量传输 │ └─────────────────────────────────────────────────────────────┘

MIG(硬件切分)/ MPS(进程组)/ Soft(单进程)三档隔离;out-of-band 传输 metadata 走 RPC,payload 直传。

Quick Start

业务侧引入 Client SDK,即可向 GPU 池提交任务

<!-- pom.xml -->
<dependency>
  <groupId>ai.lingshu.infra</groupId>
  <artifactId>lingshu-gpu-client</artifactId>
  <version>0.1.0-alpha</version>
</dependency>
// build.gradle
dependencies {
    implementation 'ai.lingshu.infra:lingshu-gpu-client:0.1.0-alpha'
}
// SubmitAndQueryDemo.java
public class SubmitAndQueryDemo {
    public static void main(String[] args) throws Exception {
        try (GpuClient client = new GpuClient("gateway.lingshu-infra:2381")) {
            String taskId = client.submit(SubmitTaskRequest.newBuilder()
                .setOpId("text_classification")
                .setInput("灵枢调度真的很强")
                .setPriority("high")
                .setTimeoutMs(200)
                .build());

            QueryTaskResponse result = client.query(taskId);
            System.out.println("status=" + result.getStatus()
                + " output=" + result.getOutput());
        }
    }
}
# application.yml — 业务 Pod 配置
lingshu:
  gpu:
    client:
      gateway: gateway.lingshu-infra:2381
      connect-timeout-ms: 3000
      retry: 3
    submit:
      default-op: text_classification
      default-priority: normal
      default-timeout-ms: 200
